# rt880-fw — правила для агентов

Прошивка Radtel RT-880 (AT32F423, BK4819 ×2, SI4732), C++/LVGL.
Актуальная раскладка клавиш и режимы — `README.md`. Глобальные правила —
`~/.config/kilo/AGENTS.md`; при расхождении важнее код и этот файл.

## Старт и сборка

- `git status --short` до правок. В worktree часто уже есть чужие изменения
  (BC SW, SI4732, spectrum и т.п.) — не откатывать и не переформатировать.
- Прошивка: `make -j4` → `build/rt880-fw-by-fagci.{elf,bin,hex}`.
- Host-превью UI: `make -C tools/preview -j4`; запуск
  `tools/preview/build/preview /tmp/kilo/ui`; PPM → PNG:
  `python3 tools/preview/topng.py /tmp/kilo/ui`.
- Юнит-тестов нет. Проверка = сборка + host-превью и точечный разбор кадров.
- Не собирать всё после каждой строки/комментария: копить правки в пачку.

## Карта

- Клавиши режимов — в `src/modes/*.cpp` (analyser, scanner, vfo, bc_scanner,
  fc); `src/ui/spectrum.cpp` только рисует спектр и водопад — обработки
  клавиш там нет.
- `src/ui/numval.cpp` — общий редактор числовых полей (курсор, `#`/MENU,
  подтверждение, автодробь).
- `src/modes/simple_scanner.cpp` ни к одному переходу не подключён —
  мёртвый режим, не править без просьбы.
- Раскладка зон — `src/ui/screen_layout.h`; общая для сканера и анализатора.
- Пины — `src/driver/board_pins.h` (LQFP64, net’ы); не заводить пины в
  `board.h`/драйверах.
- BC ALL — `src/modes/bc_all.cpp`, общая таблица полос — `bc_bands.h`.
- Глобальные блокировка клавиатуры и выключение дисплея — `mode.cpp`;
  `LOCK`/`A1-A2`/батарея — `ui/statusline.cpp`.

## Экономия контекста

- `src/modes/analyser.cpp` (~800 строк), `scanner.cpp` (~500),
  `spectrum.cpp` (~550) целиком не читать. Сначала
  `rg -n "bool key|case KEY_|void render|onRangeChanged|NumVal_"`, потом
  `Read` ±40 строк вокруг найденного. Файлы читать `Read` с offset/limit,
  не `sed`/`cat`/`head`.
- Не выводить `git diff` всего worktree: там много чужих правок. Сначала
  `git diff --stat`, затем `git diff -U3 -- <только нужные файлы>`.
- PNG-кадры пачками не читать. Пиксели/курсор/цвет проверять Python-ом по
  PPM (в файле RGB); PNG открывать только когда важна вёрстка целиком.
- Логи сборки и превью — в `/tmp/kilo/*.log`; в ответ только `tail`/`grep`
  ошибок. Не печатать гигантскую команду линковки.
- В zsh кавычить шаблоны с `*` и backtick: `rg -n 'KEY_STAR' …`.
  Временные файлы чистить `find … -delete`, а не `rm *.ppm`.
- Временные блоки в `tools/preview/preview.cpp` — под `getenv(...)`,
  прогнать один раз и сразу удалить. Отладочные дампы не оставлять.

## UI: частые грабли

- Текст (`Printf*`) — LVGL-лейблы из пула; примитивы (`FillRect`,
  `DrawHLine`, …) — прямой DMA. Прямая заливка поверх лейбла вызывает
  `lv_invalidate`, и отложенный flush LVGL может затереть прямой пиксель.
  Для оверлея поверх лейбла (курсор ввода) использовать `FillRectNoInv`,
  при необходимости сначала `lv_refr_now(NULL)`.
- `NumVal` рисует курсор ввода; пустой буфер — пробел-заглушка, и курсор
  в начале поля попадает в её bbox. Не возвращать для курсора обычный
  `FillRect` и не прятать соседнюю границу при последовательном вводе:
  принятое значение должно оставаться видимым.
- Раскладка — `src/ui/screen_layout.h`. Зоны спектра и водопада рисуются
  напрямую DMA, LVGL туда не пишет; текст в них не размещать.
  `UI_WATERFALL_Y` — начало аппаратного vscroll.
- Тема: `gThemeLight` + `TC()`; длинный `ALARM` переключает глобально
  (`Mode_Key`). В VFO длинный `SIDE2` — это уже **фильтр**, не тема.
  Переключение темы делает `Mode_Switch(*current)`, то есть режим
  пересобирается и его состояние (диапазон анализатора, позиция сканера)
  может сброситься.
- Меняешь клавиши — сначала сверься с таблицами README и шапкой mode-файла,
  затем обнови и код, и README, и комментарии.

## Правки и проверка

- Минимальный диф; стиль и библиотеки — как у соседнего кода.
  Комментарии по-русски и только по делу.
- Требования могут меняться по ходу (например, клавиши зума/шага).
  Перед правкой перечитай последнее сообщение и не тащи старую трактовку.
- После пачки правок: `make -j4`, для UI ещё `make -C tools/preview -j4`.
  Показывать первую ошибку/причину; полный лог — в `/tmp/kilo`.
- UI-сценарии проверять существующими env-блоками (`EDIT_TEST`, `BC_TEST`)
  или одноразовым `getenv`-блоком; результаты — в `/tmp/kilo`.
- `git diff --check` перед отчётом. Не коммитить/пушить без просьбы.

## Уроки сессии — не повторять

### Зарядка / PA10 — закрыто
- **CHG-DET/PA10 (нога 43) не использовать.** Полярность CS5090E — активный
  низкий, но при зарядке устройство зависает. Изолированная сборка без
  CHG-кода, PA10, PF0 и ADC-клавиш всё равно зависла: это питание/железо
  зарядки, не прошивка. Не возвращать `charging_*`, `PIN_CHG_DET`, `CHG` в UI
  и не пытаться лечить зависание перестановкой лейблов/пинов.
- Красный светодиод при заряде — аппаратный LED зарядника, не heartbeat CPU.
  Для диагностики CPU использовать подсветку клавиатуры (PA9), зелёный LED —
  шумодав, синий/оранжевый — зарядник.
- Пользователь просил **не показывать зарядку**. Батарея — только напряжение.

### Пины и антенна
- Карта пинов — `src/driver/board_pins.h` (LQFP64, номера ног и net’ы).
  PA10 там быть не должно; PB10/PC10 — это клавиши, не PA10.
- PF0 (нога 5, `UV/HF ANT-SW`) → Q119 (NPN, high = катушка) → K200:
  `A2` = HIGH = ВЧ/HF/U8, `A1` = LOW = V/U. Короткий `ALARM` глобально
  переключает A1/A2; реле не дёргать чаще 300 мс.
- Реле **не** переключать автоматически по диапазону и **не** трогать в FC:
  иначе щёлкает. Для 800 МГц в FC пользователь вручную ставит `A2`.
- Симптом «оба состояния PF0 виснут» не означает, что виноват PF0; проверять
  изолированно, но не гонять одну и ту же гипотезу.

### FC / частотомер
- В Rust-прошивке FC нет (только спектр/скан). Эталон BK4819 — UV-K5
  `driver/bk4819.c`. REG_32: `<15:14>` время скана, `<13:1>` порог,
  `<0>` enable. Рабочие: `0x245` вкл, `0x244` выкл. Ошибка была `hz << 1`
  (писалось `0x489` вместо `0x245`) — порог не сдвигать.
- FC сам ставит фильтр через `BK4819_SelectFilter`, игнорируя ручной фильтр
  VFO; на выходе — `BK4819_InvalidateFilterCache()`. `bandAutoSwitch` по
  умолчанию выключен. Входы: BC ALL — VFO → длинный `3`, FC — длинный `4`.

### SI / BC / RSSI
- Во время **прослушивания** SI (BC HOLD/PAUSE) RSSI не читать: I2C-запрос
  щёлкает. HOLD живёт 15 с по таймеру, дальше скан; `MENU` — частичный список,
  `EXIT` — прервать. Во время поиска RSSI читать можно (звук выключен).
- VFO для SI RSSI не читает; `monitorTick` при активном SI не трогает BK
  (тоже щёлкает).
- BC ALL (VFO → длинный `3`) обходит все `BC_BANDS` на SI: калибровка полосы,
  затем проход с порогом «пол + 10 дБ», пишет в общий LOOT, после обхода
  открывает список. Полный проход ~1–2 мин. Общая таблица полос —
  `src/modes/bc_bands.h`, не дублировать в новом режиме.
- Новый режим добавлять в `tools/preview/Makefile` (`APP`) и в host-заглушки,
  если он вызывает новые железные функции.

### Глобальные клавиши (mode.cpp)
- Длинный `EXIT` — выключить подсветку LCD (`st7789_backlight_off`). Любая
  клавиша включает её и **гасится** (не выполняет действие); реализовано
  через `s_wakeKey/s_wakeSuppress`.
- Длинный `STAR` — глобальная блокировка клавиатуры; `LOCK` в статуслайне;
  повторный длинный `STAR` снимает. Поэтому длинный `STAR` больше нельзя
  занимать в режимах: в BC-сканере скорость перенесена на длинный `1`/`7`,
  в RADIO — `scanBands` на длинный `1`.
- Короткий `ALARM` — антенна A1/A2, длинный `ALARM` — тема (глобально).
- BK: короткий `SIDE1` — принудительный шумодав (toggle), короткий `SIDE2`
  диапазон не листает. SI: `SIDE1/SIDE2` — следующий/предыдущий диапазон.
  `SIDE1` длинный — группа, `SIDE2` длинный — фильтр AUTO/HF/VHF/UHF/800.

### Статуслайн / LVGL
- В статуслайне **нет CHG**. Метки: заголовок x=8, `LOCK` x=70, `A1/A2`
  x=132, напряжение x=169, батарея x=207. Не добавлять CHG-лейбл обратно.
- LVGL-куча на железе 12 КБ, в host-превью 512 КБ; превью не показывает
  нехватку объектов. Держать число лейблов минимальным.
- Не делать вывод о зависании по красному LED/новым лейблам: сначала
  изолировать (без CHG/PF0/PA10/ADC) и использовать подсветку клавиатуры как
  heartbeat. Временные heartbeat/маяки убирать после диагностики.

### Клавиатура
- `key_raw_direct[DIRECT_COUNT]` раньше писалась индексами ADC — это был
  OOB. Не заводить общий фиксированный массив под matrix+direct+ADC; в
  `process_key` передавать локальный `bool pressed`.
- ADC-клавиши (SIDE1/SIDE2/ALARM) на PC2; PC0/PC1 — SI I2C; не путать.
  При заряде CHG-DET уводит KEYIN-AD, но CHG-режим из прошивки удалён.
